# 翠嵐麻雀 — 対局エンジンと COM の仕様

## 公開 API

ブラウザーと Node.js 共通の ESM。描画・時刻・DOM に依存せず、操作は同期的な状態遷移になる。

```js
import { MahjongGame, AI_PERSONAS } from '../dist/js/core/game.js';
import { chooseAIAction, analyzeHand } from '../dist/js/core/ai.js';

const game = new MahjongGame({ players: 4, length: 'east' }, 20261017);
const actions = game.getActions(0);
game.act(actions.find(a => a.type === 'discard'), 0);

// 描画側のタイマーから一回ずつ呼ぶ。人間の判断待ち・局終了なら false。
const advanced = game.stepAI();

const saved = game.serialize();
const resumed = MahjongGame.restore(saved);
const paifu = game.exportPaifu(); // JSON 文字列
```

| API | 内容 |
| --- | --- |
| `new MahjongGame(rules?, seed?)` | ルールを正規化し、東一局の配牌と親の最初のツモまで行う。文字列・整数の seed に対応。 |
| `.state` | 保存可能な完全な対局状態。COM の隠し手牌・山の並びも含むため、推論や公開表示へそのまま渡さない。 |
| `.getActions(player = 0)` | その座席が今選べる操作の配列。手番外、回答済みの鳴き待ち、終局は空配列。 |
| `.act(action, player = 0)` | `getActions` に返された操作を実行する。異なる牌 ID、手番違い、不正な和了は例外。 |
| `.stepAI()` | COM の打牌または鳴き応答を一回実行し、実行時 `true`、人間待ち・終了時 `false`。 |
| `.nextHand()` | `handEnd` から次局へ進む。連荘・本場・場風・親を更新し、新しく配牌する。 |
| `.setPersona(player, id)` | 対局中の COM の個性を変更する。牌姿と点数は引き継ぐ。人間席への設定は自動検証時にも使用。 |
| `.getPublicState(viewer = 0)` | その席から観測できる手牌・河・副露・北抜き・表ドラと得点のコピー。山、王牌、裏ドラ、隠れた他家の手牌、過去の他家ツモを除く。 |
| `.serialize()` | 物理牌・点棒を検証後、形式名とバージョン付きの保存 JSON を返す。 |
| `MahjongGame.restore(json)` | JSON を検証し、そのまま判断待ちから再開する。重複牌、欠損牌、余分な点棒、非対応バージョンを拒否。 |
| `.exportPaifu()` | 開始 seed・ルール・COM 設定・選択操作・全イベント・得点・最終精算を JSON に出力。 |
| `.validateState()` | 牌の一意性、全牌数、三麻の萬子制限、面子の構成、手番と手牌枚数、王牌枚数、槓数、点棒総額を検証。 |

### 操作オブジェクト

すべて `type` と表示用の `label` を持つ。`getActions` が返した同じオブジェクトを渡すこと。追加フィールドを送っても判定に使われず、不正な組合せは受理しない。

| `type` | 主なフィールド | 意味 |
| --- | --- | --- |
| `discard` | `tileId` | 手牌を一枚切る。 |
| `riichi`, `openRiichi` | `tileId` | この牌を切って宣言。聴牌、門前、供託資金、残り山を確認済み。 |
| `tsumo`, `ron` | `tileId` | 役、符、翻、フリテンなどを満たす和了。 |
| `chi`, `pon` | `tileIds`, `forbiddenTypes` | 自分の手牌から出す牌 ID。鳴かれた捨て牌は別途エンジンが加える。 |
| `minkan` | `tileIds` | 大明槓。 |
| `ankan` | `tileIds` | 暗槓。リーチ後はツモで得た四枚目で、待ち不変かつ標準設定では面子構成も不変の場合のみ。 |
| `kakan` | `tileId`, `meldIndex` | 加槓。搶槓の応答を先に集める。 |
| `nuki` | `tileId` | 三麻の北抜き。 |
| `pass` | — | 鳴き・ロンを見送る。ロンを見送った場合はフリテンも更新。 |
| `abort` | `reason` | 九種九牌の申告。 |
| `next` | — | 次の局へ進む。人間席にだけ返す。 |

牌選択自体は UI の状態であり、いつでも変更できる。`act(discard)` を実行した後の取り消しはない。エンジンは合法な操作しか受け取らず、「取り消したつもりで次の COM の行動まで進んだ」という中間状態を作らない。

## 状態の主要フィールド

| 項目 | 内容 |
| --- | --- |
| `phase` | `discard`、`response`、`handEnd`、`matchEnd`。 |
| `turn`, `dealer` | 手番と親の座席。人間は常に 0。 |
| `roundIndex`, `roundWind`, `handNumber` | 場の通算番号、27〜30 の東南西北、各場の局番号。三麻は各場三局。 |
| `honba`, `riichiPot` | 本場と供託の千点棒数。オープンリーチの複数千点棒もここへ積む。 |
| `wall`, `deadWall`, `remaining` | 生牌山、常時 14 枚の王牌、生牌山の残数。嶺上牌を引いた分は生牌山の末尾から王牌へ補充。 |
| `doraIndicators`, `uraIndicators` | 有効な表示牌。これらは `deadWall` の参照であり、物理牌総数へ二重計上しない。 |
| `lastDraw` | `player`、`tile`、`source: wall / rinshan / nuki`、最新カンドラの位置。 |
| `lastDiscard` | 捨てた座席、牌、リーチ宣言牌か、槓直後か、通常ツモ後か。 |
| `response` | 捨て牌または槓に対する応答。`source`、`tile`、`kind`、座席ごとの `choices`。 |
| `players[i].hand` | その座席が持つ実牌。ツモ牌も含む。 |
| `players[i].drawnTileId` | 手牌中のツモ牌を識別する ID。副露直後は `null`。 |
| `players[i].melds` | `kind`、実牌配列、鳴いた相手 `from`、鳴いた牌の ID `calledTileId`。 |
| `players[i].discards` | `{ tile, riichi, called, tsumogiri? }`。鳴かれた牌は河に記録を残すが、実体は副露に所属。 |
| `players[i].nuki` | 抜いた北の実牌。 |
| `players[i].riichi`, `.doubleRiichi`, `.openRiichi`, `.ippatsu` | リーチ状態。宣言の応答中だけは `.riichiPending`。 |
| `players[i].temporaryFuriten`, `.riichiFuriten`, `.discardFuriten` | 同巡内、リーチ後見逃し、自分の捨て牌によるフリテンを区別。 |
| `players[i].firstCallEvidence` | 初回副露直後の手牌・副露の記録。先付けの時系列条件へ使用。 |
| `players[i].pao` | 大三元・大四喜について責任者の座席を記録。 |
| `players[i].revealed` | 和了や聴牌流局で手牌を公開する座席。オープンリーチは別途 `.openRiichi`。 |
| `event`, `events`, `log` | 最新の演出イベント、直近 32 イベント、対局全体の記録。各イベントに増加する `id` がある。 |

### イベント

`{ id, type, player, tile, details }` を返す。型は `deal`、`draw`、`discard`、`chi`、`pon`、`kanDeclared`、`ankan`、`minkan`、`kakan`、`nuki`、`riichi`、`openRiichi`、`ron`、`tsumo`、`exhaustiveDraw`、`abortiveDraw`、`handEnd`、`matchEnd`。`kanDeclared` は暗槓・加槓を宣言した未成立の応答段階で、`details.kind` に槓の種類が入る。搶槓を見送って成立した時点で別途 `ankan`・`kakan` が出る。

誰も鳴けない打牌は、同じ `act` 内で次のツモまで進む。その場合 `event` は最新のツモだが、`events` と `log` には打牌も残る。描画側はイベント ID の差分、または前後の盤面差分を使う。

## 和了・流局の結果

```js
state.result = {
  kind: 'ron', // tsumo / exhaustive / abortive
  title: 'ロン和了',
  reason: null,
  winners: [{
    player: 1,
    from: 0,
    score: { valid: true, han: 3, fu: 40, yaku: [], payments: {} },
    tiles: [], // 和了牌を含む完成した伏せ手部分
    melds: [],
    pao: []
  }],
  tenpai: [],
  deltas: [-5200, 5200, 0, 0],
  continueDealer: false
};
```

ロンでは勝者の実 `hand` へ放銃牌を追加しない。同時ロン時に一枚の牌を複数の手へ所属させないためで、完成形の表示には `result.winners[].tiles` を使う。牌の物理的な所属は放銃者の河のまま。

終局では `state.standings` に `player / name / score / rank / uma / oka / result` が入り、`result` は千点単位。オカ有効時は返し点との差と全員分の持ち点差をトップへ加える。オカ無効時は持ち点との差で精算する。同点は起家順。終局時に残った供託はトップへ移す。

## 採用した進行細則

基本役の基準は [日本プロ麻雀連盟・麻雀の役](https://www.ma-jan.or.jp/activity/yaku.html)。追加役の名前と由来の参照は [麻雀祭都ミラー](https://mjradio.web.fc2.com/majansite-mirror/index.html)。追加役には流派差があるため、実際に採用した牌姿と翻数は `rules.js` の `YAKU_CATALOG` と `docs/RULES.md` に明記する。

- 四麻は人間一人と COM 三人。三麻は人間一人と COM 二人で、萬子の 2〜8 を除く 108 枚、チーなし。
- リーチは門前で聴牌し、供託後に残り山が人数分以上ある場合に宣言可能。暗槓は門前を維持する。
- リーチ宣言牌にロンが入った場合、宣言は未成立で供託を取らない。誰もロンしなければ供託を取り、その後の鳴きで一発を消す。
- 同時ロンをすべて集めてから、複数和了・頭ハネ・三家和流局の設定を適用。複数和了時の供託は放銃者に最も近い下家の勝者へ、本場は各勝者へ加える。
- ロン優先、その後にポン・大明槓、最後に直下家のチー。鳴き応答を集める間は牌を消費しない。
- 食い替えは禁止。同一牌の切り戻しに加え、チーの両端を入れ替える筋食い替えも禁止する。
- リーチ後はツモ切り、和了、待ち不変の暗槓、ツモ牌の北抜きだけが可能。暗槓は待ち牌集合が変わらないことを比較し、標準の厳格設定ではすべての和了分解に対象の独立した暗刻があることも確認する。面子構成が変わる暗槓を認める「待ち牌のみ不変」設定もある。[Mリーグ公式ルール](https://m-league.jp/about/) のリーチ後暗槓条件を厳格設定の参照にしている。
- 加槓は他家の搶槓応答後に成立する。国士無双の暗槓搶槓は設定に従う。搶槓された槓を面子・槓数・新しい表ドラに加えない。
- 暗槓のドラ表示は直後。明槓・加槓は設定で成立直後または嶺上牌の打牌後。連続槓では先行する未表示ドラを次の槓成立時に表示する。
- 嶺上開花・搶槓の最新カンドラを数えるかはそれぞれ設定する。未表示の候補と通常の表示牌を別に渡し、二重計上を防ぐ。
- 北抜きの補充は生牌山から行い、槓数・カンドラを増やさず、嶺上開花・海底摸月とは扱わない。北抜きが一発を消すかは設定。第一巡の無中断条件は北抜きでも終了する。
- 北抜きは独立の抜きドラと、北が表示ドラの場合のドラを重複して数える。北抜きの枚数だけで通常役の存在を代用しない。
- 四槓散了は複数人で四回目の槓が成立した後、嶺上和了とその打牌へのロンを優先してから流局。一人で四槓した場合は続行し、五回目の槓は不可。
- 四風連打は鳴きも槓も北抜きもない最初の四人の捨て牌が同じ風の場合。三麻には適用しない。全員リーチの流局設定は三麻では三家立直になる。
- 通常流局では牌姿から聴牌を判定し、聴牌者を公開する。聴牌の親の連荘、和了だけの連荘、すべての流局で連荘、途中流局時の連荘を設定できる。
- 不聴罰符の任意総額を人数で割り切れない場合は 100 点棒単位で分け、余りの 100 点棒を起家順に割り当てる。四麻 3,000 点、三麻 2,000 点の標準値は均等に割り切れる。
- 責任払いは第三の三元牌、第四の風牌を最後に鳴かせた座席を記録する。責任のある役満分だけを分け、他の複合役満は通常払い。ツモは責任者、他者のロンは責任者と放銃者でその役満分を折半。
- 三麻のツモ損有無は点数計算側で処理する。本場はツモ時に各支払者が 100 点、ロン時に放銃者が 300 点。完全な責任払いのツモでは本場も責任者へまとめる。
- 流し満貫は全捨て牌が么九牌、どれも鳴かれていない、標準設定では副露なしの場合に満貫ツモとして処理する。複数人の成立も可能。聴牌は不要。個別の門前・副露翻数や役満倍数を変更した場合はその設定で精算し、ドラは加えない。0 翻指定なら成立せず、二翻縛り設定も反映する。
- 最終局のトップ親の和了止め・聴牌止め、返し点未満の延長、最大の延長場数、飛びの境界を設定できる。

## COM の判定

`AI_PERSONAS` に十二人の個性を数値で公開している。重みは速度、打点、守備、鳴き、リーチ、染め、対子、ドラ、役満、読みの十項目で、それぞれ 0〜100。

打牌候補ごとに次を比較する。

1. 捨てた後の向聴数。通常形、七対子、国士無双などは共通の向聴計算を使う。
2. 自分の手牌と公開された河・副露・北抜き・表ドラを引いた受け入れ枚数。
3. 現物、筋、壁、役牌の残り枚数、染めている副露などから計算した危険度。
4. リーチや深い副露のある相手に対し、自分の聴牌距離・残り巡目・守備の個性から押すか降りるかを変える。
5. 手牌に残るドラ、赤牌、役牌対子、染め色の比率、対子数、国士や大三元・四暗刻の種を個性に応じて評価する。

鳴きでは鳴いた後の打牌まで向聴数を比較し、役牌・クイタン・染め・対々和などの役の見込みがない開いた手を避ける。鳴き速攻型と門前リーチ型で閾値が違う。和了が合法ならどの COM も和了する。牌を透視する AI ではなく、河からの危険推定も確率的な保証ではない。

`analyzeHand(state, player)` は `{ shanten, ukeire, threat, bestShanten, candidates }` を返す。候補は `tileId / type / red / shanten / ukeire / accepts / danger / utility` を含む。必ずその席の `getPublicState` を渡すこと。

## 検証

```sh
node --test --test-isolation=none tests/*.test.mjs
```

`tests/game.test.mjs` は実牌を山から一枚ずつ割り当てる局面作成関数を使い、存在しない五枚目の牌を含む検証局面も拒否する。

配牌、三麻の除外牌、違法操作、保存復元、同時ロン・頭ハネ、鳴き優先順位、食い替え、フリテン、リーチ宣言直後の放銃、ダブル・オープンリーチ、暗槓と王牌補充、遅延カンドラ、搶槓、国士暗槓搶槓、リーチ後暗槓の待ち比較、北抜き、九種九牌、責任払い、改変された保存ファイルを検証する。固定 seed の全自動対局では毎操作後に全牌と全点棒を照合し、終局までの停止や枚数破壊を検出する。

和了形・符・翻・ドラ・役満・各ローカル役の点数検証は `tests/scoring.test.mjs` に分離している。

2026 年 10 月 17 日の追加連続検証では、三麻・四麻をそれぞれ 20 対局、合計 40 対局を実行した。内訳は東風戦 24、東南戦 8、一荘戦 8。十二種類すべての COM を含み、先付け・中付け、頭ハネ、ツモ損なし、遅延カンドラ、オープンリーチ、ローカル役を切り替えた。319 局・16,964 操作が終局まで進み、毎操作の牌・点棒照合と 50 操作ごとの保存復元はすべて成功した。固定 seed は三麻 `413000 + index * 197`、四麻 `414000 + index * 197`、各 `index = 0..19`。これは進行エンジンの確認であり、ブラウザーの描画確認とは別である。

## v1.1.0: COM抽選

`aiPersonas` は `random` と従来の12種類のIDを受け付けます。省略時は全席 `random`。三麻でも設定には3枠を保持し、生成するCOMは2人です。`state.players[].persona` は抽選済みの実IDです。抽選用の乱数は牌山用から分離し、局進行と保存復元で再抽選しません。固定IDの既存設定・保存データは維持します。
