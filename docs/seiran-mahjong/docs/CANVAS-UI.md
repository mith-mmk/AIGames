# 描画フレーム内のUI — v1.1.0

## 描画の構成

可視領域は1枚のWebGL Canvasです。Three.jsによる自動卓の描画と、Canvas 2Dで作成したUIテクスチャの描画を同じ画面に合成します。UIのためのHTMLボタン、フォーム、手牌要素、ダイアログ、スクロール領域はありません。ブラウザがJavaScriptを起動する最小の `index.html` と、画面サイズ・余白を制御するCSSだけを残しています。

`ui/layout.js` は現在のフレームの幅・高さとセーフエリアを受け取り、ヘッダー、他家表示、卓、手牌、操作列、モーダルの領域を計算します。親ウィンドウの画面サイズは参照しません。ページ全体はスクロールせず、設定・図鑑・記録は描画領域内でページを送ります。

`ui/canvas-ui.js` は文字、牌、枠、ボタンを描き、同じ矩形から入力判定を登録します。`ui/screens.js` は手牌、設定、数値入力、COM選択、保存、牌譜、役図鑑、鳴き、結果、分析の各画面です。ゲーム状態の遷移と保存は `app.js`、麻雀の判定は従来の `core/` に分離しています。

UIは正投影で合成し、照明・霧・トーンマッピングを適用しません。牌の色はv1.0.1の濃い印刷色のままです。選択不能時も牌面を薄くしません。横長では手牌を1行、縦長の狭い画面では2行に収めます。

## サイズ変更と描画負荷

Canvasの解像度は表示寸法と端末の画素密度を基準にし、画素密度2とGPUの最大テクスチャ寸法を上限にします。リサイズ時にはUIテクスチャのGPU領域を作り直し、旧テクスチャを破棄します。同じGPUテクスチャへ異なる寸法のCanvasを再アップロードすると古い画面が残るケースをブラウザ検証で検出したため、この処理を明示しました。

3D卓の描画はオフスクリーン描画先に保持します。牌、カメラ、アニメーション、画面サイズに変化があるときに更新し、ボタンへのマウス移動や設定のページ送りだけでは3Dの全形状・影を描き直しません。最後に卓の画像とUIを可視Canvasへ合成します。

## 入力

ポインター座標はCanvasの矩形から現在のフレーム内座標へ変換します。UI・モーダルに対するポインター操作はキャプチャ段階で処理し、背後のOrbitControlsへ伝播させません。モーダルを開いている間はカメラ操作も停止します。

Tab／Shift+Tabで操作を選び、Enterで実行します。PageUp／PageDown、ホイール、上下スワイプでページを移動し、Escapeで戻ります。通常の手牌では左右キー、Enter、R、N、Spaceを利用できます。打牌を確定するまでは選び直せますが、確定後の取消は行いません。

ファイルの選択とダウンロードはブラウザの標準機能を利用します。ファイル選択APIが使えないブラウザでは、DOMに追加しない一時的な `input[type=file]` を標準ファイル選択画面の呼び出しだけに使います。これは画面上のゲームUIとして表示・配置するものではありません。読み込み対象は保存・牌譜JSONで、進行状態を検査してから反映します。

## COMの抽選

設定の初期値は `['random', 'random', 'random']`。三麻では先頭2席を使い、3席目は将来の四麻切り替え用に保持します。固定タイプとの混在も可能です。

対局を新しく生成するときに12種類から席ごとに独立抽選します。重複は許可します。選ばれたタイプと名前は `state.players` に保存し、連荘、次局、途中保存からの復元では変更しません。既存の固定指定も維持します。

抽選の乱数列は牌山用と分離しています。COMの設定変更だけで、同じseedによる山・配牌・サイコロが変わることはありません。

## 制約

Canvasの文字は個別のDOMテキストではないため、標準的な読み上げソフトによる項目単位の読み取りには制限があります。キーボード操作とCanvasの説明は実装していますが、DOM UIと同等のアクセシビリティを保証するものではありません。

今回の最小検証サイズは横長568×320・800×300、縦長320×568です。これを下回る極端に小さい枠で全項目を操作できることは未検証です。物理的な画面面積そのものが小さい場合、3D卓も小さくなります。
