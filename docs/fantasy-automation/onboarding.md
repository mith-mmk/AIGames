# 初回案内の改善と検証

2026-10-13。ユーザーの「ゲームのやり方が全然わからない」という指摘に対応。

## 改善前に分からなかったこと

初期画面は7設備と「採掘機・魔導炉・魔力炉を設置」という一文だけで、最初に押す設備・クリックする鉱脈・配置順・接続の向きが特定できなかった。魔力0から木材補給へ進む導線も、操作完了から次の操作へ進む確認もなく、メニュー内の長文配置例と座標照合が必要だった。改善前の画像は `artifacts/fantasy-automation/onboarding/before-first-screen.png`。

## 画面で一段ずつ進む案内

- 「この設備を選ぶ」→光る区画へ左クリック。設備選択と出力方向の設定だけを行い、建設はプレイヤー自身が行う。
- 地図の目印に設備名・座標・向き、カードに現在の段階・具体的な次の操作を表示。
- 初回ライン9設備→木材1個補給→最初の自動納品→木材採取場と燃料ベルト3設備、全14段階。
- 補給は実装済みの「設備の詳細を開く」→「手動補給」で木材・個数1→「補給する」。架空のデモ起動・自動配置ボタンは案内しない。
- 魔力生成10秒など正常な待機と、誤方向・断線・滞留・資源不足を区別。条件を満たすと次へ進む。
- 目標が画面外なら設備選択時にカメラを移して目印を表示。自由なカメラ操作は維持。
- 建設直後の成功表示を、同じ区画の「設備があります」で即座に上書きしない。
- 「案内を閉じる」で自由建設へ。「メニュー」→「はじめての案内」で再表示。

案内判定は `onboarding.ts` の純関数。シミュレーションの規則・保存形式version1・保存枠は変更しない。保存を消去したり、案内を開くだけで建設・素材消費したりしない。初回納品済みの自由配置工房を見本の位置へ作り直すよう強要せず、既存工房の燃料経路も判定する。

## 検証方法

実装担当（UI・描画・案内ロジック）と初心者QA担当を分けた。QAは画面に出ている文・ボタン・目印の実際の位置だけから進行し、既存の配置座標やゲームの内部状態を注入して完成させていない。保存の保持確認だけはIndexedDBを読み取り、状態を比較する。

- Node: 案内10テスト。14段階から自動100本まで、誤方向、異設備、素材不足、納品後の導線切断・復旧、搬送修理、自由配置、正常な魔力待機、非破壊性。
- 既存全テスト＋新作38件、TypeScript、lint、Git管理した配布JSと再ビルド結果の一致検査。
- source／Pages梱包版で、案内だけを追って最初の自動納品と燃料自動化まで到達。
- 故意に向きを間違える、通電中に導線を切る、案内で直して再開。
- 案内の終了→自由建設→再表示。5回の開閉でも保存状態が完全一致。ページを再読込し「読込」した既存工房でも開閉・保存一致。
- 390／320幅でもタッチ操作で一段ずつ進む。CTAの高さ44px以上、横はみ出しなし、目標区画がUIで覆われないことを確認。
- 従来のブラウザQAをsource／梱包版とも再実行。保存、回転、複製、撤去、連続敷設、resize、WebGL復旧・fallbackを保持。
- `.pages-dist/` だけを `/AIGames/` 配下でHTTP配信し、同梱JS/CSS/Three.jsの読み込みと建設を再確認。

`npm run playtest:fantasy-guide`、`node scripts/fantasy-automation-onboarding.cjs --built` で再実行。記録・スクリーンショットは `artifacts/fantasy-automation/onboarding/source/` と `built/`。

実機のSafari/Firefoxや実ユーザー全員の理解度を保証する検証ではない。ブラウザ操作の確認はChromium151/SwiftShader。mainマージ・公開は行っていない。

目視上の軽微な残件: 390幅では目印ラベル上端が案内カードと一部重なる場面がある。区画の目印・クリック先は覆われず、設備名・向きはカード内にも表示される。全14段階のタッチ進行は成功している。
