# 魔導からくり工房 — 構成と実装範囲

Library の「貼り付けたテキスト.txt」企画 v0.1 全579行を確認。ブラウザ、Three.js、TypeScript、Vite、ローポリ・デフォルメ、OrthographicCamera、32×32シードマップ、20Hz固定ステップを採用する。

MVPは採掘→搬送→精錬→搬送→納品箱。鉄の延べ棒100本は初期段階の達成目標。第2段階は魔晶原石・精製魔晶・魔導剣、技術ツリーによる物流・結晶加工の分岐と実測量産。第三段階は魔導核・鉄の躯体・ゴーレムの製造と収納箱からの自律補給。第四段階は錬金精髄・転送核・世界樹の種を追加し、離れた送受信門による物流を経て世界樹を育成する。

## 既存構成との共存

- `AGENTS.md` に従い各作品の入口は独立HTML、タイトルは `AI Games`、コードは `web/js/`、CSSは `web/css/`。
- 新作だけTypeScriptをVite library buildで `web/js/fantasy-automation/runtime/app.js` に変換。配布JSもGit管理してビルドなしHTTP配信を可能にする。既存HTML・JavaScriptの配信方式を変えない。
- 同梱済みThree.js 0.180.0をHTML importmapで参照。型と開発ビルド用npm packageも同版。外部CDN・他社参考画像の転用なし。
- `npm start` の前と `npm run build:pages` の前に新作をビルドする。Pagesのコピー許可リストはTSやテストを公開しない。
- 既存Three.js LICENSEを保持。GLBや物理応答は今回不要。将来GLB採用時は梱包拡張子とloader追加が必要。
- 作業ブランチ `feat/fantasy-automation`。mainマージ・Pages公開は今回行わない。Pages workflowはmain更新と手動実行でのみ稼働。

## 担当とAPI

[interfaces.md](interfaces.md) と第2段階の [technology-interfaces.md](technology-interfaces.md) を共有境界とする。Simulationがplain state/命令/20Hz更新を所有し、描画はstateを読む。カメラやDOM状態は保存しない。入力はcanvasでのみ地形へ渡す。保存はIndexedDB 1枠、版管理と厳密な検証を行う。

## 不足仕様の補足

- 設備1×1区画、出力は矢印側、入力は隣接セルから受け入れる。0北/1東/2南/3西。
- 木材・鉱石はMVP中に枯渇しない。初期資材から自給できるよう森林と鉱脈を中央に保証。
- 建設費はデータ定義。導線は木材1、ベルトは木材1+延べ棒1。設備キットを優先消費。
- 手動補給した鉱石・延べ棒は自動納品に含めない。手動燃料補給は採掘機で生まれる鉱石の自動属性に影響しない。
- タブ非表示では進行を停止。オフライン進行はMVP外。速度0/1/2はゲーム内時間のみ変える。

## 検証

固定ステップ、資源保存、更新順依存、採掘から精錬、配線切断/復旧、詰まり復旧、自動100本のクリア、手動納品除外、保存再開をNodeで検証。Playwright/Chromiumでsource/built両方の起動、実入力、反復操作、320/390/desktopリサイズ、WebGL状態、スクリーンショットを確認。既存 `npm test` とPages梱包を実行する。CI待機は行わない。

## 初回案内

`onboarding.ts` は現在のゲーム状態から次の操作を求める純関数。14段階の見本配置、補給、最初の自動納品、燃料自動化を案内し、向き違い・断線・滞留を診断する。ゲーム規則や保存形式は変更しない。UIと地図の目印は任意表示、案内を閉じても自由建設できる。

## 第2段階

研究、生産速度、FIFO収納、分岐器、混合素材の予約、旧セーブ移行はシミュレーション側で処理する。描画とUIは状態を読む。研究未解放の建設・レシピ選択は命令層でも拒否する。保存v2では研究と生産履歴、手動取出し履歴を保持する。具体的な条件と追加設定は [technology.md](technology.md) を参照。

## 視覚UI・第三段階

収納スロット、登録式建設ショートカット、動的目的はDOMで表現し、ショートカット設定はIndexedDBのゲーム保存と別に保持する。ベルトと設備は形の異なる接続印と方向を3D表示する。ゴーレム補給は固定ステップで、実在する物品を収納箱から対象設備へ移す。

保存v3で第三段階を追加し、v1/v2は歴史的なスキーマを厳密に検証してから移行する。詳細は [stage3.md](stage3.md) と [visual-ui.md](visual-ui.md)。

## 第四段階

全12資源・21設備・9レシピ・12研究。転送はシミュレーション内で実物1個を移動し、通過履歴と手動操作履歴を保持する。同一番号に送信1台・受信1台だけがある場合に動作し、送信側だけで魔力を消費する。世界樹は自動生産・未手動・転送済みの種を消費して成長する。描画側は役割・番号・搬送・成長の状態を読む。

保存v4はv1/v2/v3の歴史スキーマを先に検証してから移行する。ゴーレム案内も純関数で、ゲーム状態を変更しない。検索・ショートカット・パネル・撤去確認はDOMの責務。撤去確認中の一時停止と入力遮断はアプリ側で管理し、保存対象にしない。[stage4.md](stage4.md) に条件と検証をまとめる。
